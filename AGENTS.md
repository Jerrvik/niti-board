# Инструкции агенту Codex — проект «Нити»

1. **Язык общения и отчётов — русский.** Названия внутренних переменных могут быть английскими. Пользовательские тексты — RU (основная) + EN (желательная дополнительная локализация).
2. Прочитай `CODEX_START_RU.md`, `docs/ТЗ_RU.md`, `docs/UX_RU.md`, `docs/АРХИТЕКТУРА_И_РИСКИ_RU.md`, `tests/ПРИЁМКА_RU.md` до больших изменений.
3. `src/niti-board` — реальные исходники первой BETA, не финальный результат. Можно рефакторить или заменить iframe/архитектуру, если это улучшает стабильность в Foundry V14. Сохранять простоту и визуальную концепцию.
4. Проверяй используемые Foundry API по **V14** в документации и, при наличии, по локальной установке. **Не утверждай** совместимость с V14.361/V14.364 без соответствующих тестов.
5. Истина — **единое публичное состояние доски** в world data, сохраняемое авторизованным GM. Не использовать глобальные широковещательные сообщения для секретов: секретных слоёв в этой версии нет.
6. Проблемы авторизации и подделки отправителя, конфликтов правок, удаления объектов, утечек неразрешённых актёров, ошибок после перезагрузки являются блокерами. Не заменяй безопасность одной скрытой кнопкой.
7. Правки нескольких игроков не должны молча теряться. Если требуется сериализация через GM, очередь/ACK/revision/resync и сообщения об ошибках реализуй и покрой тестами.
8. Проверь drag & drop из Actor Directory в отдельное окно/iframe; если реализация нестабильна, измени устройство интерфейса. NPC не должен требовать ручного повторного ввода имени/портрета.
9. Не добавляй большие зависимости/фреймворки только ради небольшой доски. Все зависимости документируй. Не вставляй внешние картинки/шрифты по умолчанию, если можно работать с локальными ресурсами.
10. Сначала `npm test` и доступные статические проверки, затем реальные тесты Foundry. Не выдавай браузерный макет за полноценную многопользовательскую проверку.
11. Сборка GitHub: `module.json` с публичным стабильным `manifest` и версионным `download`, release ZIP, инструкции. Реальный GitHub URL сообщай только после публикации и проверки, **не выдумывай**.
12. При неизвестной авторизации `gh auth status`; попроси пользователя войти безопасным штатным способом. Перед публикацией проверь наличие репозитория и утечек. Для спорных/необратимых действий запроси подтверждение, если оно требуется.
13. Не изменяй согласованную продуктовую суть: одна доска, все игроки могут создавать и редактировать связи. Стикеры и области второстепенны. Не заменяй её журналами и сложным трекером расследований.
14. В финальном отчёте: что сделано, что проверено, что НЕ проверено, как установить, GitHub Repo + Manifest + Release + ZIP, известные ограничения, отличия от исходной BETA.

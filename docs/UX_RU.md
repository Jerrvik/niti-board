# UX / UI: как должна ощущаться «Нити»

## Визуальная концепция

- Тёмная графитовая доска, слегка бордовые/приглушённые акценты, светлый читаемый текст. Атмосферно под VTM, но не имитировать официальные защищённые бренды/логотипы.
- Доска — **главное**, панели инструментов — вторичные. Не более пяти постоянных действий: выбор, карточка, стикер, связь, область.
- Не копировать тяжёлые журналы Foundry. Свободный текст стикера и подпись линии редактируются непосредственно и без длинных форм.
- Фото NPC — крупные/компактные по выбору. Портрет не должен растягиваться в искажённую пропорцию.
- Визуальный ориентир — `docs/interface-reference.png`, но допускается улучшать детали.

## Мини-сценарии

### Сценарий 1: мастер представляет трёх NPC
1. Открывает Actor Directory и окно доски рядом.
2. Перетаскивает «Князь» → на доске карточка с фото/именем.
3. Перетаскивает «Шериф» и «Примоген».
4. Расставляет карточки по смыслу.

### Сценарий 2: игрок строит отношения
1. Выбирает инструмент **Связь**.
2. Нажимает на «Князь», потом на «Шериф».
3. Видит новую линию, подписывает **«Подчиняется»**, выбирает стрелку, указывающую от шерифа к князю (при необходимости разворачивает направление).
4. Мастер и другие игроки видят результат, даже если сами доску не меняли.
5. Игрок позже меняет подпись на «Присягнул» либо меняет цвет.

### Сценарий 3: групповые догадки
1. Игрок создаёт область «Камарилья».
2. Располагает в ней NPC; ещё одну область называет «Под подозрением».
3. Добавляет стикер «Кто передал сведения?». Не нужно ничего заполнять помимо текста.

### Сценарий 4: мастер защищает важный NPC
1. GM ставит защиту карточке князя.
2. Игрок пытается удалить князя: получает понятное предупреждение.
3. Игрок по-прежнему может создать/удалить **связь** с князем.

### Сценарий 5: нет мастера
1. GM выходит или теряет соединение.
2. Игрок видит доску, но не может создать несохраняемые правки.
3. При возвращении GM вновь доступно редактирование/авторизованная запись.

## Элементы управления

- Левый блок: пять инструментов с понятными названиями, не только иконками.
- Центр: панорамируемый и масштабируемый холст, линии под карточками, но доступные для выбора.
- Правая компактная панель: параметры **выбранного** объекта; если ничего не выбрано — краткая инструкция.
- Быстрый маршрут: создать карточку → соединить → подписать, **без модальных окон на каждом шаге**.
- Небольшой статус: «Сохранение… / Сохранено / Нет GM / Конфликт — обнови».
- Пустая доска должна объяснять добавление NPC из списка Foundry. В игровой версии не создавать фиктивных «канонических» NPC автоматически.

## Особое внимание

- Связь должна легко попадаться под курсор (невидимая широкая интерактивная область вокруг тонкой линии).
- Для нескольких связей одного NPC к другому нужен разнос кривых/линий или выпадающий выбор; нельзя, чтобы подписи лежали друг на друге.
- При перемещении узла связи следуют визуально **во время drag**, но сетевой commit — в конце/с debounce.
- «Сохранено» показывать только после подтверждённого сохранения на авторитетном клиенте/сервере, не после локальной перерисовки.
- При длительном имени ника/имени NPC кнопки и интерфейс не исчезают (учитываем проблему прошлых модулей).
- По возможности избегать слишком маленьких click targets и анимаций, отвлекающих от игры.

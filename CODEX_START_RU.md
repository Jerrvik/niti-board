# Задание Codex: доработать «Нити» и опубликовать для тестирования

**Цель:** на основе переданного исходного модуля `src/niti-board/` сделать полноценную, удобную для мастера и игроков **BETA-версию модуля Foundry VTT 14**; провести доступные проверки, собрать установочный ZIP и опубликовать исходники и GitHub Release, чтобы мастер мог установить модуль через **Manifest URL**.

Это самостоятельный новый модуль «Нити» (id: `niti-board`), никак не связанный с `Right to Speak`. Первая сборка `0.1.0-beta.1` уже содержит интерфейс и первичную логику, но **совместная работа внутри Foundry с несколькими пользователями не подтверждена**. Не считать существующую реализацию финальной.

## Порядок работы

1. Изучи исходники и документацию. Запусти имеющиеся проверки. Составь короткий список дефектов и технических решений.
2. Исправь и доведи редактор до требований `docs/ТЗ_RU.md`, уделяя главное внимание ручному построению/редактированию связей, drag & drop актёров, синхронизации и сохранению.
3. Приведи UI к концепту `docs/UX_RU.md`; сохрани тёмную палитру, компактность и простоту.
4. Добавь автотесты модели, конфликтов, сериализации, проверок прав, загрузки/сохранения и корректности импортируемых JSON. Не делай фальшивых мок-прохождений: отчёт должен отделять доступные проверки от реальной Foundry.
5. Если доступна локальная Foundry V14, проверь модуль в тестовом мире как GM и игрок. Цель совместимости — **V14.361 и V14.364**, но если доступен только один билд, честно укажи это. Реальную проверку с GM + двумя игроками отрази отдельно.
6. Подготовь установочный ZIP с правильным путём `niti-board/module.json` и release manifest.
7. Подготовь публичный GitHub-репозиторий и BETA GitHub Release согласно `docs/GITHUB_RELEASE_RU.md`. Сначала проверь `gh auth status`; если нет доступа — попроси авторизацию и продолжи после неё. Не запрашивай токен в чате.
8. Проверь публикацию `manifest` и ZIP по HTTPS и установочную структуру. Если публикация невозможна, всё равно предоставь ZIP и точные следующие действия, но не утверждай, что GitHub готов.
9. В конце предоставь **четыре ссылки**: репозиторий, Manifest URL, релиз, ZIP; приложи отчёт проверок и ограничений.

## Важные критерии

- Игрок может создать и подписать связь между двумя NPC без мастера, присутствующего у клавиатуры, **если GM-клиент подключён для авторизованной записи**.
- Игроки могут исправлять и удалять связи; перемещённая карточка не отрывается от линий.
- Мастер добавляет NPC из каталога Foundry одним drag & drop (имя и фото), игроки добавляют доступных им актёров.
- Одна общая доска для всех, сохранение между сессиями, нет журналов и скрытых слоёв.
- У мастера есть возможность защитить важную карточку от случайного удаления игроками. Это **не должно** запрещать связь к такой карточке.
- Нет молчаливой потери подтверждённых правок при совместной работе, после перезагрузки — актуальная схема.
- Если мастер офлайн, виден честный read-only / unavailable статус, без ложного «сохранено».
- Продуктовые тексты и тесты оформлены по-русски; установочная инструкция понятна мастеру.

**Не останавливайся после этапа планирования.** Доведи реализацию до установочной тестовой сборки. Эскалируй только реальный блокер безопасности, невозможность выполнения действия из-за авторизации/отсутствия доступа или принципиальное изменение требований.

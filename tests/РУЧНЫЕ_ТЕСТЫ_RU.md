# Ручные проверки в Foundry V14 — инструкция GM

Сначала **сделать бэкап мира или создать пустой тестовый**. Не включать в рабочей хронике до результатов теста. В мире нужны минимум три пользователя: GM, Игрок A, Игрок B. Раздельные браузерные профили/окна, независимые сессии, общий Foundry URL.

## Короткий сценарий (10–15 минут)

1. GM устанавливает BETA в тестовый мир, активирует в настройках модулей. Должна появиться кнопка запуска «Нити».
2. GM открывает окно, держит Actor Directory справа. Перетаскивает доступного NPC на поле: проверяет имя и портрет.
3. GM перетаскивает второго NPC, игрок A добавляет третью карточку вручную.
4. Игрок A создаёт связь между первыми NPC, подписывает «Подчиняется», включает стрелку; у GM и игрока B это появляется автоматически.
5. Игрок B меняет цвет связи и перемещает NPC. Все видят изменение, линия остаётся привязанной.
6. A и B создают **две разные** связи между одной парой NPC. Оба должны иметь возможность редактировать нужную связь независимо.
7. Игрок A делает стикер, игрок B — область «Камарилья». Проверяется ввод текста и перенос элементов.
8. GM блокирует карточку князя. Игрок A не может удалить **карточку**, но может создать к ней новую линию.
9. GM выходит/теряет соединение: A видит статус просмотра и не получает ложного сохранения. GM возвращается.
10. Перезагрузка всех трёх окон: сохранены карточки, линии, подписи, рамки и текст.

## Обязательная параллельная проверка

- A перетаскивает NPC-1, B перемещает NPC-2 практически одновременно. Проверить, что обе операции есть после refresh.
- A и B одновременно меняют одну подпись. Убедиться, что выбранная политика конфликта ясна и нет молчаливой потери **уже подтверждённых** данных.
- Отправить повтор одного `opId` в тестовом окружении; не должно появиться двух элементов.
- Ввод `<img src=x onerror=alert(1)>` в заметку и подпись не должен выполняться как HTML.
- Попытка импортировать JSON с огромным фото и несуществующими узлами должна показать ошибку без разрушения доски.

## Drag & drop: проверки прав

- NPC с правом видимости для всех → успешно доступен игроку.
- NPC, видимый только GM → игрок не должен узнать скрытое имя/портрет из доски без осознанной публикации GM.
- GM намеренно публикует скрытого NPC на **публичную доску** → предупреждение перед публикацией.

## Отчёт от мастера

- Foundry: `14.361` / `14.364` / другое; система (если применимо); браузеры/OS.
- Пара скриншотов: до/после создания связи.
- Какие 3 действия были удобны? Какие 3 — раздражали?
- Замечались ли лаги, пропажи изменений, конфликты?
- Вопрос главной ценности: **может ли игрок сам быстро создать и исправить отношения между NPC без помощи GM?**
- При сбоях: последовательность действий, текст ошибки, F12 → Console (без токенов и частных данных).
